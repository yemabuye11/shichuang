## 🔧 修复「打开站点要先点回首页才能显示」(commit 59b72e5)
- **症状**：野马反馈「打开网站需要再点一个回首页才能显示」。每次打开都先到 404 页（"这个页面找不到了"），点回首页按钮才看到主页。
- **根因**：`src/router.tsx` 用 `createBrowserRouter(routes)` 未传 `basename`。部署在 GitHub Pages 项目页 `/shichuang/`，URL pathname 为 `/shichuang/`，router（默认 basename `/`）拿整段当路由匹配 → 无任何 route 匹配（routes 都是 `/`、`/square` 等相对根）→ 落到 `*` → 渲染 NotFoundPage（含「回首页」按钮）。点 `<RouterLink to={ROUTES.HOME}>` 后再次匹配同一路径——野马描述的现象与 NotFound 行为一致。
- **修复**：`createBrowserRouter(routes, { basename: import.meta.env.BASE_URL })`。`BASE_URL` 在部署构建（`--base /shichuang/`）下为 `/shichuang/`，本地 dev 为 `/`，两环境通吃。
- **顺手修**：`vite.config.ts` 的 `navigateFallback: 'offline.html'` 引用了不存在的文件（部署脚本只生成 `dist/404.html`，没生成 `offline.html`），SW 的导航兜底实际是断的——改成 `'404.html'`（与 SPA 兜底一致，globPatterns 已把它纳入 precache）。
- **验证**：`tsc --noEmit` 0 错（沙箱最初因两步 Edit 留了隐藏的解析错，clean rewrite 后通过）；`vite build --base /shichuang/` ✅ exit 0，1260 模块，dist 产出正常，PWA precache 59 entries/2241 KiB（three 747KB 已按 globIgnores 排除）。
- **教训**（写进 GO_LIVE_STEPS/DOC 候选）：任何 GitHub Pages 项目页 + React Router BrowserRouter + Vite，**`basename` 必须用 `import.meta.env.BASE_URL`**；PWA 的 `navigateFallback` 必须指向**真实存在的** SPA 兜底文件（通常是 `404.html` 或 `index.html`）。
