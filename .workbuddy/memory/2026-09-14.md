## 🔑 积分过期调度入口（engineer-10 已答，建库后必须配）
- 入口：**`public.void_expired_credits(p_user_id uuid default null)`**，定义在 `0020_credit_expiry.sql` **第176行**，SECURITY DEFINER，传 null = 全量清扫；授权只给 service_role（0020 第372行），老师端调不了。
- 现状：**唯一调用点是 `reserve_credits` 里的 `perform void_expired_credits(v_uid)`（0020 第244行）**，即"该用户生成时才顺带对自己作废"；**无 Edge 路由、无 pg_cron**。
- ⚠️ **纠正此前判断：不配调度 ≠ 赠送积分能多花**。两侧已堵死：① 消费侧 reserve_credits 扣费前先 void 再校验余额 → 过期积分根本花不出去 ② 展示侧 get_my_summary/admin_list_users 已剔除"已过期未作废" → 余额显示就是真实可花余额。
- 不配调度的**真实后果**（都不是"能多花"）：`credit_accounts.balance` 列虚高（自写统计SQL会读错）/ **无 `reason='expire'` 流水→ 老师积分明细看不到"已过期"这一条，对账缺一环** / credit_lots 过期 lot 的 remaining 不清零缓慢堆积 / total_earned 不回退。
- **建库后配置（方案A pg_cron，零运维，可直接给野马执行）**：
  ```sql
  create extension if not exists pg_cron;
  select cron.schedule('void-expired-credits-daily','17 3 * * *',
    $$select public.void_expired_credits(null);$$);   -- UTC 03:17 = 新加坡 11:17
  select * from cron.job;                              -- 查看
  select cron.unschedule('void-expired-credits-daily');-- 取消
  ```
  `cron.schedule` 默认以 postgres 角色执行，能调 SECURITY DEFINER 函数，无需额外授权。
- **建议先手动跑一次** `select public.void_expired_credits(null);` —— 新库应返回 0，确认不报错再挂 cron。
- 方案B（Edge 路由用 service_role 调该 RPC）目前 `supabase/functions/` 下**没有这个路由**，需要时约10行可补。
