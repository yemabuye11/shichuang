## 🐞 0037 广场种子 SQL 报错修复（commit `4324593`）
- 野马在 SQL Editor 跑 `0037_square_seed.sql` 报错，截图指向 `convert_to`。先 Grep 复核：仓库里 10 处 `convert_to($hN$<html>$hN$, 'UTF8')` **第二参本来就是 'UTF8'**（正确），说明他跑的是**旧文本副本**（对话里早先贴的那版）。
- **真 bug 在下一行**：`encode(x.raw, 'sha256')` —— PostgreSQL 的 `encode(bytea, text)` **只支持 base64 / hex / escape 三种格式**，`'sha256'` 不是合法格式。正确写法是先哈希再 hex：`encode(sha256(x.raw), 'hex')`（`sha256(bytea)` 是 PG11+ 内置，Supabase PG15 OK）。已 replace_all 修 10 处。
- ⚠️ 通用知识（以后写 SQL 别再踩）：`encode` 只做**编码**（base64/hex/escape）；`sha256()/md5()/digest()` 才做**哈希**。`convert_to(text, '编码名')` 第二参是字符集名（UTF8/GBK/LATIN1），不是哈希算法名。
- 重跑安全性：整个种子在一个 `do $$ ... $$` 块里，报错即整块回滚，`apps` 表无脏数据；且每条都有 `where not exists(title=...)`，重跑不会重复插入。
- ⚠️ 流程教训：给野马 SQL 让他跑之前，我应该**直接给文件/告诉他从仓库最新文件复制**，而不是在对话里贴长文本——贴出去的旧版本会被反复执行。已改为 `present_files` 直接给文件。
