# 内测前交付分工方案

| 角色 | 任务 | 预期产出 | 完成标准 |
|---|---|---|---|
| 产品经理 | 冻结 P0/P1 范围；确认教材上传、知识复用、3D 导出口径；收集十份低质量文档清单 | 更新 `docs/PRD_REMAINING.md`、决策记录、删除清单 | 用户故事和验收标准无歧义；十份文档有明确 ID/环境/归属 |
| 架构师 | 梳理真实生成依赖、迁移顺序、Storage 路径、RLS、回滚与环境变量 | 真实联调清单、迁移/回滚方案、风险评审 | 能从登录到生成逐项定位；不需要把密钥写入前端 |
| 前端工程师 | 修复教材空状态；增加新建版本/上传入口；接入上传状态、知识管理和错误态 | 生成页/教材组件/相关 hooks 与 services 的实现 | 空库可创建；上传可反馈；创建后自动选中；无页面卡死 |
| 后端工程师 | 验证/修复真实 generate、教材解析沉淀、文档 Storage 版本、积分退款、RLS | Edge Functions、迁移、RPC/服务层变更 | 真实账号生成成功；失败退款；版本可回读；越权请求被拒 |
| 数据/知识工程师 | 设计电子教材解析、切片、去重、来源和 verified/pending 状态；制定 Skill 命中规则 | 解析任务方案、字段映射、知识质量规则 | 知识可追踪来源；撤回后不再命中；不同学校隔离 |
| QA 工程师 | 做 Mock、真实 Supabase、移动端、分享、权限、重复提交、失败退款回归 | 测试记录、缺陷清单、内测门禁结论 | P0 验收标准全部有证据；阻断问题关闭或明确豁免 |
| 运维/发布 | 核对迁移、Secrets、Functions、GitHub Actions/Pages、备份和监控 | 发布记录、回滚点、线上 smoke 结果 | 构建和 Functions 发布成功；线上地址可注册、生成、分享 |
| 交付总监 | 管理依赖和单一 owner；组织评审；决定是否达到内测门禁 | 里程碑看板、风险升级、最终放行结论 | 无未评估 P0 风险；每项遗留有 owner 和下一步 |

## 建议执行顺序

1. 产品经理确认十份文档清单、教材上传边界、真实环境和 3D/PPT 口径。
2. 架构师完成真实环境检查；后端先修生成/Storage/退款硬阻塞。
3. 前端补教材空状态、创建/上传和知识管理入口。
4. 数据/知识工程师接入解析、审核和复用规则。
5. QA 做端到端回归；运维按清单发布；交付总监做内测放行。

同一文件只设一个 owner。跨角色改动必须在 `docs/logs/` 记录影响面、验证范围和未完成项。
