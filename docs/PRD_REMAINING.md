# 师创剩余功能简版 PRD

- 版本：v0.1（内测前收口）
- 日期：2026-09-15
- 目标：围绕“生成页主入口、教材绑定、真实生成、文档可用、知识持续沉淀”冻结剩余需求
- 非目标：本版不改变整体技术栈，不把应用广场改为首页，不执行未确认的批量删除

## 1. 用户与目标

### 目标用户

中小学教师，尤其是需要快速生成教案、PPT/课件和办公文档，并希望内容贴合本校教材进度的备课教师。

### 内测目标

让教师能从根路径进入生成页，选择或创建教材版本，生成一份可核对、可编辑、可导出的教案/课件，并把经教师确认的知识安全沉淀，供后续生成复用。

## 2. 用户故事与验收标准

### US-01 生成页作为默认首页（P0）

**用户故事**：作为已登录教师，我打开网站后希望直接开始生成，而不是先进入应用广场。

**验收标准**：

- 已登录访问 `/` 直接显示生成页；刷新后仍保持。
- 未登录访问 `/` 显示公开首页，点击 CTA 后进入登录/生成流程。
- `/square` 仍可独立访问，任何导航不把它设置为默认首页。
- GitHub Pages 子路径部署下根路径、`/generate`、`/square` 均不出现 404。

### US-02 绑定已有教材（P0）

**用户故事**：作为教师，我希望按年级、学科、出版社、版本和章节选择教材，让生成结果贴合当前教学进度。

**验收标准**：

- 级联筛选顺序和当前已有版本数据一致，筛选后可选版本不会出现跨维度错误。
- 选中版本和章节后提交请求携带 `textbookVersionId` 与章节文本。
- 生成进度出现教材检索阶段；结果展示“AI 生成，请教师核对”提示。
- 没有绑定教材时仍可生成，且不会卡在教材检索阶段。

### US-03 新建教材版本与上传电子教材（P0）

**用户故事**：作为第一次使用某套新教材的教师，我希望在绑定教材的位置直接创建版本并上传电子教材，不必跳到无关页面。

**验收标准**：

- 当版本列表为空或筛选无结果时，显示明确的“新建教材版本/上传电子教材”入口。
- 创建表单至少包含年份、年级、学科、出版社、版本，可选章节；必填校验清晰。
- 创建成功后自动刷新级联选项并选中刚创建的版本。
- 上传文件有类型/大小限制、进度和失败提示；文件权限遵循当前用户/学校范围。
- 上传成功后能看到“待解析/待核对”状态，不能把未核对内容标成已验证。

### US-04 真实生成教案/课件（P0）

**用户故事**：作为教师，我希望输入一句话需求后得到真实可用的教案或课件，而不是只看到示例或错误。

**验收标准**：

- 使用真实 Supabase 配置、活动 prompt、模型 Secrets 和有效积分时，教案请求能完成理解、教材检索（如适用）、生成、校验、存储、结算。
- 失败、超时、校验失败或存储失败时显示可理解的错误，预扣积分按规则退款。
- 成功结果包含标题、学科、年级、正文、核对提示，并能从生成页打开文档运行页。
- Mock 示例明确标记为演示，不得作为真实质量验收结果。

### US-05 在线编辑、版本和导出（P0）

**用户故事**：作为教师，我希望修改 AI 文档、保存版本并导出 Word/PPT，便于直接使用。

**验收标准**：

- 只有作者或明确授权角色能进入编辑和保存操作；公开查看链接无需登录。
- 保存生成新版本，版本号递增，刷新后能回读最新版本。
- DOCX/PPTX 导出文件可打开，标题、段落、标题层级和主要列表不丢失。
- 导出失败不丢失当前编辑内容，并给出重试提示。
- 3D 课件至少提供网页交互查看；PPT 静态呈现方式需在内测前确认并记录。

### US-06 教师知识沉淀（P0）

**用户故事**：作为教师，我希望把核对后的教材补充和生成经验保存下来，让下一次生成更贴合本校教材。

**验收标准**：

- 教师可以对教材版本新增/编辑/删除章节知识；来源区分教师、AI 检索和上传解析。
- AI 检索结果默认 `pending`，教师确认后才进入可复用知识。
- 后续生成优先命中当前版本已确认知识，并在结果中标示来源/核对状态。
- 删除或撤回知识后，后续检索不再命中；操作有审计记录。
- 不同教师/学校的数据按 RLS 隔离，不能通过前端参数越权读取。

### US-07 文档定向清理（P1，需确认清单）

**用户故事**：作为管理员，我希望删除指定的低质量演示文档，不误伤真实用户内容。

**验收标准**：

- 删除前展示 ID、标题、作者、来源、创建时间和影响范围。
- 只接受明确 ID/筛选结果的定向删除，不提供清空整表/整桶按钮。
- 删除同步处理应用记录、文档版本、Storage 对象和内容库索引，失败可重试。
- 记录操作者、时间、删除原因；必要时先备份。
- 用户提供十份文档的精确清单并确认线上/Mock范围后，才能进入实现。

### US-08 内测质量门禁（P0）

**用户故事**：作为交付负责人，我希望在发给教师前确认核心流程稳定。

**验收标准**：

- `npm run typecheck`、`npm run build`、Edge 语法体检全部通过。
- 至少完成一次真实 Supabase 端到端生成和一次失败退款验证。
- 完成桌面端、移动端、分享链接、作者权限、重复提交和刷新恢复测试。
- 发布记录包含构建版本、迁移版本、Functions 版本、Secrets 检查结果和已知问题。

## 3. 优先级与依赖

| 优先级 | 功能 | 前置依赖 |
|---|---|---|
| P0 | 教材空状态新增/上传入口 | `textbook_versions`、Storage、RLS |
| P0 | 真实教案生成排障 | Supabase 迁移、活动 prompt、模型 Secrets、积分 |
| P0 | 文档真实保存/回读 | docs Storage、作者权限 |
| P0 | 知识审核和复用 | `textbook_knowledge`、审计/撤回策略 |
| P0 | 内测回归门禁 | 以上功能完成 |
| P1 | 定向删除十份文档 | 用户提供精确 ID/范围 |
| P1 | 导出保真和 3D PPT 策略 | 内测样例与产品确认 |

## 4. 关键业务规则

- 首页默认是生成，不是应用广场。
- 生成结果必须提示教师核对；AI/外部检索内容默认不能直接标为 verified。
- 教材电子版、校本资源、生成知识沉淀分开存储和授权。
- 积分先预扣，失败/超时/校验失败/存储失败按统一规则退款。
- 任何删除必须定向、可审计，禁止用清空表或 Storage 桶代替。
- 所有真实密钥只存在 Supabase Secrets；前端和日志不得出现密钥。
