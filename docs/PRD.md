## 一、原始需求复述（新定位）

客户需要一个**面向中小学教师的 AI 备课办公台**：教师用一句自然语言描述需求，平台帮其生成**教案、PPT 课件、3D 课件、其他办公文档**；平台能让教师随教材版本变化生成贴合内容（如今年初三数学换新教材），并让 AI 联网检索对应版本教材内容。生成结果以**网页链接（可演示/分享）**、**可编辑的在线文档**、**导出 .pptx / .docx 文件**等多种形态交付，方便教师在 PowerPoint / WPS 中继续修改、投屏、打印、交教研。

客户已拍板的四条关键决策（来自刚结束的澄清）：
1. **3D 形态：两者都要**。简单内容用**伪 3D 动画课件**；几何/物理/化学/生物等用**可旋转、可拆解的真实立体模型（Three.js 真 3D）**。这是和飞象老师拉开差距的亮点。
2. **输出格式（多选，都要做）**：① 网页版可演示（生成链接直接打开讲、能分享，零成本，和现有架构一致）；② 导出真正的 `.pptx`（老师用 PowerPoint/WPS 改、投屏）；③ 导出 `.docx` 教案（老师改、打印、交教研）；④ 生成后必须支持修改。
3. **支持修改**：生成的教案/PPT/课件老师要能改。落地两条腿：网页版生成后进入**在线编辑态**（改文字/结构）；导出 PPTX/Word 后在 Office 里改。注意：**文档类（教案/PPT/课件）必须支持在线编辑，列为 P0 核心**；"P0 不提供在线代码编辑器"的约束**仅针对原"应用类"**，不约束文档类。
4. **教材版本知识机制（核心差异化）**：老师生成时通过**多窗口级联选择**「年份 / 版本（如 2024 版）/ 出版社（人教版、北师大版…）」；平台让 AI **联网搜索该版本教材内容**；生成后老师**核对内容对错**（AI 可能编错，必须显著提示"请教师核对"）；老师可**手动补写正确内容**，或**上传电子版教材**，平台据此修正并沉淀。把"选教材版本"做成多窗口级联选择组件。

已定且不变的项目事实（沿用，不重写）：平台名「师创」/ 代号 shichuang；登录邮箱+密码+邀请码；多模型适配器（DeepSeek 主 + 至少一家备份，客户自购 Key）；会员/套餐+积分、线下充值、不做在线支付、兑换码+管理员后台唯一回收通道；先海外后国内部署；网页+PWA 先行预留原生 APP/小程序；现有 8 类应用类型已有基础，其中 **AI 教案·大单元 / 互动课件 / 教学动画** 已有基础，新需求是在此基础上升格为主轴并补强。

## 二、产品定义

### 2.1 产品定位（一句话）

> **师创 = 教师的 AI 备课办公台：教案、PPT、3D 课件、办公文档，说一句就生成；自带教材版本机制，永远跟得上新教材。**

差异化（相对飞象老师）：
- **更聚焦"备课办公"**：主轴是教案/PPT/3D 课件/文档，而非"做应用"；
- **自带 3D**：伪 3D 动画课件 + Three.js 真 3D 可旋转可拆解模型，和飞象老师拉开差距；
- **自带教材版本机制**：选年份/版本/出版社，AI 联网检索该版本内容并提示教师核对，应用类平台没有。

### 2.2 Product Goals（3 个正交目标）

| # | 目标 | 可度量标准 |
| --- | --- | --- |
| G1 | **降低备课生产门槛**：非程序员教师零学习成本产出可用的教案/PPT/3D 课件/文档 | 未用过的教师，无人指导下 5 分钟内拿到第一份可编辑教案/PPT；首次生成可用率（产出可编辑/可演示结果）≥ 90% |
| G2 | **教材贴合且可校验**：生成内容贴合所选教材版本，且显著提示教师核对、可修正沉淀 | 生成页强制出现教材版本级联选择；结果页 100% 出现「请教师核对」显著提示；教师可一键补写/上传修正 |
| G3 | **多形态输出 + 成本可控可感知**：网页/链接/PPTX/Word 多形态交付，平台方付得起账 | 同一生成物可一键导出 PPTX 与 DOCX（保真度达预期阈值，见待确认 Q3）；单次生成模型成本有硬上限告警；教师 2 次点击内看到剩余额度与本次消耗 |

### 2.3 User Stories

1. As a **九年级语文教师**，I want 说一句"出一份《岳阳楼记》两课时教案"就拿到结构化教案，so that 我不用从零写、改改就能交教研。
2. As a **初三数学教师**，I want 生成"圆柱与圆锥"的**可旋转可拆解 3D 课件**，so that 学生能直观理解几何体展开与体积关系（新教材换版也能跟上）。
3. As a **教务主任（野马本人）**，I want 给教研组批量发一套统一模板（教案/PPT），so that 全组备课格式一致、可直接复用。
4. As a **使用平台的教师**，I want 生成后**核对并修正 AI 编错的教材内容**（手动补写或上传正确电子教材），so that 发给学生的是对的，平台还能越用越准。
5. As a **上课的教师**，I want 把 PPT/课件生成**网页链接直接投屏或发班级群**，so that 学生手机打开即用、无需安装。
6. As a **普通教师用户**，I want 清楚看到还剩多少额度、本次生成花了多少，so that 我不会突然"做不了了"。

| P0-C2 | **PPT 课件生成** | 产出可被"演示视图"渲染的课件结构，并**一键导出 .pptx**（见 P0-F）。演示视图 = 网页版可演示形态 |
| P0-C3 | **课件生成（2D / 伪 3D 动画）** | 分段讲解 + 小检测 + 可跳转目录；简单 3D 用 CSS/SVG 伪 3D 动画（互动课件已有基础，升格主轴） |

| P0-J4 | 埋点 | 注册、生成次数、生成成功率、各类型分布、导出次数、分享点击、核对修正次数（验证 G1/G2/G3） |
| P0-J5 | 架构可扩展预留 | 数据访问走统一 service 层；预留原生 APP/小程序与国内迁移 |

### 3.1 提示词工程专项需求（P0 核心，决定产品成败）

**目标**：约束大模型稳定产出「教学可用、贴合教材版本、可编辑、可导出」的备课文档/课件/3D，以及原有的单文件 HTML 应用。

#### 3.1.1 系统提示词结构（固定前缀，放最前命中上下文缓存，降低约 30 倍输入成本）

1. **角色设定**：「你是资深教研专家 + 教育技术专家，擅长把教师需求实现为可直接用于课堂的教案、PPT 课件、3D 课件与办公文档。」
2. **输出格式硬约束**（按类型区分，见 3.1.2）：
   - 文档类（教案/办公文档）：输出**结构化可编辑文档**（平台约定的 JSON/HTML 富文本结构），不输出裸散文；
   - 课件类（PPT/伪 3D）：输出**幻灯片结构 + 每页内容/动画说明**，平台渲染为演示视图并支持导出；
   - 3D 类：输出**HTML + 内联 Three.js 场景描述**（几何体/材质/交互），自包含；
   - 应用类：沿用 v1 单文件 HTML 约束（全部内联、不引用外部 CDN、≤200KB）。
3. **教学性约束**（本产品核心差异）：
   - 明确学习目标；即时反馈（作答即判对错+解析）；进度/成就机制且防挫败；
   - 语言/示例/难度贴合指定年级学科，不超纲、不成人化；
   - 界面简体中文，字号足够大（正文 ≥16px，按钮 ≥44px）。
4. **教材版本感知约束**（见 3.1.3，核心）：严格贴合所选年份/版本/出版社/学科/年级，**不臆造教材内容**，不确定处必须显式标注。
5. **安全合规**：不生成政治敏感/暴力/色情/赌博/迷信等未成年人不适宜内容；不收集学生姓名/班级/手机号/位置等个人信息；不得发起未授权的外部网络请求。

#### 3.1.2 备课文档类提示词（教案 / PPT / 课件结构）

| 类型 | 子提示词要点（结构骨架） |
| --- | --- |
| **教案** | 字段：课题/年级学科/课时/教材版本 → 教学目标（知识/能力/素养）→ 教学重难点 → 教学准备 → 教学过程（环节：情境导入/新授/活动/小结/作业，每环节含时间、师生活动、设计意图）→ 板书设计 → 作业布置 → 教学反思（留空待填）。排版清晰可打印 |
| **PPT 课件** | 输出幻灯片数组：每页含 标题/正文要点/图示说明/动画或交互建议/备注；约定页数（默认 12–18 页）、风格简洁、字号层级；分页逻辑贴合教案环节；便于 pptxgenjs 映射 |
| **课件（2D/伪3D）** | 分段式讲解 + 每节后小检测 + 可跳转目录；简单立体感用 CSS transform/SVG 透视，标注"伪 3D"；配播放/暂停/重播 |

#### 3.1.3 教材版本感知提示词（核心差异化）

将 `年份 / 版本（如 2024 版）/ 出版社（人教版、北师大版…）/ 学科 / 年级` 作为**强制注入字段**，约束：

- 生成内容**必须严格贴合该版本教材的章节、知识点、术语与难度**，不得混用其他版本表述；
- **不得臆造**教材中不存在的篇目、公式、定义、例题；
- 对无法确认是否准确的细节，**必须显式标注「⚠️ 待教师核对」**并在结果中留出可编辑位；
- 优先采用平台检索/沉淀的该版本教材内容作为依据（见 P0-D）。

#### 3.1.4 3D 课件提示词（何时真 3D / 模型枚举）

**判定规则**：
- 简单示意、流程、概念类比 → 用**伪 3D 动画课件**（CSS/SVG），更快更轻；
- 几何/物理/化学/生物等需空间理解的实体 → 用 **Three.js 真 3D 可旋转、可拆解模型**。

**真 3D 模型类型枚举**（提示词可枚举并让用户选）：
- 几何体：正方体/圆柱/圆锥/球/棱锥的展开与截面；
- 函数图：y=f(x) 曲面、参数曲线；
- 分子：水分子/甲烷/DNA 双螺旋；
- 地球仪：经纬网、自转公转、板块；
- 电路：串并联、基本元件连接（可交互通断）；
- 生物：细胞器、人体器官剖面；
- 物理：杠杆/滑轮/透镜成像。

真 3D 提示词要求：输出自包含 HTML（Three.js 走 CDN 或本地打包）、默认可旋转、关键部件可点击拆解/标注、移动端可触控操作。

#### 3.1.5 输出校验与自修复（P0 细化）

1. 文档类：校验结构字段完整、无 `TODO`/`...` 省略占位、尺寸合理；
2. 3D/应用类：提取代码块，校验闭合、无残留 Markdown、体积上限、无 `eval` 滥用；
3. 校验失败 → 携带具体错误重试 1 次；二次失败 → 友好错误 + 「重试」+ **不扣积分** + 记日志。

#### 3.1.6 成本优化（P0 必做）

- 系统提示词作固定前缀放最前，命中 DeepSeek 上下文缓存（差约 30 倍）；
- 默认 DeepSeek-V4-Flash（便宜），复杂类型可选 Pro；
- 控制 `max_tokens`（文档类建议 8K，3D/应用类视复杂度）。

## 四、关键技术约束与成本红线（给架构师的硬要求）

### 4.1 成本实测数据（v1 撰写时 2026-08 公开数据，价格持续上涨，**仅作量级参考**，上线前必须复核；架构不得依赖具体价格）

**DeepSeek API（元 / 百万 tokens，峰谷定价；高峰 = 北京时间 9:00–12:00、14:00–18:00）**

| 模型 | 时段 | 输入(缓存命中) | 输入(未命中) | 输出 |
| --- | --- | --- | --- | --- |
| V4-Flash | 空闲 | 0.05 | 1.5 | 4.5 |
| V4-Flash | 高峰 | 0.10 | 3.0 | 9.0 |
| V4-Pro | 空闲 | 0.15 | 4.5 | 13.5 |
| V4-Pro | 高峰 | 0.30 | 9.0 | 27.0 |

> ⚠️ 模型**定价会变动且已多次上涨**（v1 曾一次调价涨幅最高达 1100%）。**平台必须把"成本"与"用户看到的积分"解耦**，否则模型一涨价前端数字全改。这是「积分制 + 全局支出上限」的首要原因。

**结论**：新用户赠送积分（按会员档，见六）的模型成本可控；**必须设全局月度支出上限告警**。教师备课高峰恰落高价时段，P1 可做"非高峰更省"引导。

### 4.2 Supabase 免费层红线（务必遵守，否则突然不可用）

| 资源 | 免费额度 | 风险 |
| --- | --- | --- |
| 数据库 | 500 MB / 项目 | 文档/应用 **HTML 不要存数据库字段**，只存元数据与产物引用 |
| 文件存储 | 1 GB（单文件 ≤ 50MB） | 教材上传、3D 资源注意体积 |
| 出网流量 | 10 GB（5GB 出网 + 5GB 缓存出网） | ⚠️ **最大风险**：热门内容被大量打开会击穿 |
| Auth MAU | 50,000 | 充足 |
| Edge Functions | 500,000 次/月 | 充足（教材联网检索走这里） |
| 无活动暂停 | 连续 1 周无访问自动暂停 | 假期后可能"打不开"，需健康检查/定时唤醒 |

**架构硬要求（P0）**：
1. 文档/应用 HTML **不走数据库**，存 Storage 或对象存储；
2. **必须走 CDN / 静态托管缓存后再分发**（Cloudflare Pages / Vercel 带宽充裕），Supabase 只承担「元数据 + Auth + 生成接口 + 教材检索 Edge Function」的轻量流量；
3. 应用类单文件 ≤ 200KB（提示词 + 上传双层限制）；
4. 前端合理缓存头与分页（广场每页 ≤ 24 条）。

### 4.3 安全红线

- 应用类生成物在 **iframe `sandbox`** 中运行，**不授予 `allow-same-origin`**，防窃取平台会话；
- **API Key 绝不下发前端**，只在 Edge Function / 服务端调用；
- 数据库 **RLS 全开**：用户只能改自己的内容，广场/运行页只读；
- 生成内容显著标注「AI 生成」+ 提供举报入口（合规底线）；
- **PPTX / Word 导出是前端库（pptxgenjs / docx）在浏览器端生成，不增加服务端成本、不触发出网风险**——这是成本红线下的友好设计。

### 4.4 给架构师的技术铺垫（仅标注，非架构方案）

> 以下为产品侧标注，供架构师评估方案，本文档不规定具体实现。

1. **文档类产物形态差异**：文档类（教案/PPT/课件）生成物是 **HTML/富文本（或结构化 JSON）**，需**新的产物存储与渲染策略**（编辑态、演示视图、导出映射），与"应用类纯单文件 HTML"不同，不能简单复用现有单文件托管方案。
2. **3D 引入 Three.js**：真 3D 需引入 Three.js，**注意包体积与移动端性能**（懒加载、按需引入、降低多边形数、触控交互）；迁移国内后 CDN/本地化策略需一并考虑。
3. **教材联网检索落点**：是 **Edge Function 里调用搜索/模型**，还是**前端直接调**？涉及 **API 成本、密钥安全、合规（境内检索来源）**。P0 需先定方案（见待确认 Q1）。
4. **多模型适配器**：DeepSeek 主 + 至少一家备份，客户自带 Key；服务端统一代理，支持热切换。

## 九、MVP 验收标准（建议）

1. 新教师从打开链接到拿到第一份可编辑教案/PPT ≤ 5 分钟（无人指导）；
2. 首次生成可用率 ≥ 90%（教案/PPT/课件/3D/应用各测 10 次）；
3. 教材版本级联选择可用，且生成内容出现「请教师核对」显著提示；
4. 同一内容可一键导出 PPTX 与 DOCX，且网页演示链接可分享、未登录可打开；
5. 文档类生成后可在在线编辑态修改并保存；
6. 积分扣减准确：成功扣、失败退、并发不超额；
7. 单次生成模型成本 ≤ 0.1 元（Flash 高峰口径）；Supabase 出网 < 5GB/月（靠 CDN 分流）。
