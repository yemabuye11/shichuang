# 师创项目现状报告

- 盘点日期：2026-09-15
- 盘点范围：当前工作区全部项目目录、`docs/`、`.workbuddy/memory/`、前端源码、Supabase migrations/functions、Git 历史与构建配置
- 本轮原则：只读盘点，不修改业务代码、数据库、Supabase 资源或 GitHub 部署

## 一、项目定位与当前主流程

师创是面向中小学教师的 AI 备课办公台。产品主轴已经从“做互动应用”调整为“生成教案、PPT/课件、办公文档，并结合教材版本知识”；互动应用、每日一练、组卷/题库、内容库、充值和管理后台是并列能力。

当前推荐主流程是：登录 → 进入生成页 → 选择产物大类 → 输入一句话需求 → 可选绑定教材/章节/模板/公开课 → 生成 → 预览、核对、编辑 → 导出或分享。根路径对已登录用户直接渲染生成页；应用广场是独立的 `/square` 路由，不应成为默认首页。

## 二、技术栈与工程结构

| 层级 | 当前实现 |
|---|---|
| 前端 | React 18、TypeScript、Vite 5、React Router 6 |
| UI | MUI 6 + Tailwind CSS 3 |
| 数据与鉴权 | Supabase Auth、Postgres、RLS、RPC、Storage |
| 服务端 | Supabase Edge Functions（Deno/TypeScript） |
| 文档能力 | DocModel 结构化 JSON、平台渲染壳、TipTap 编辑、`docx`/`pptxgenjs` 结构化导出 |
| 互动与 3D | 应用 HTML 沙箱预览；Three.js 按需动态加载，避免首屏预缓存 |
| 本地演示 | `mockStore` + IndexedDB；无 Supabase 配置时可演示主要流程 |
| 发布 | GitHub Pages + GitHub Actions；Edge Functions 独立部署 |

主要目录职责已在根目录 `AGENTS.md` 固化：`src/pages` 页面流程、`src/components` UI、`src/services` 数据访问、`src/hooks` 状态、`src/types` 共享类型、`supabase/migrations` 数据库变更、`supabase/functions` 服务端生成/检索/存储/积分。

## 三、已完成部分

### 3.1 产品和页面

- 生成页支持应用/文档两条路径；文档可多选教案、PPT、2D 课件、3D 课件、办公文档等格式。
- 已登录根路径进入生成页；应用广场 `/square` 保留为独立导航。
- 生成中页面支持阶段进度、取消、失败重试、积分刷新和应用/文档分流预览。
- 文档运行页 `/d/:id`、文档编辑页 `/d/:id/edit`、应用运行页 `/app/:id` 已接入路由。
- 文档支持在线查看、作者编辑、版本保存入口、公开链接复制、内容库发布开关和 AI 核对提示。
- 已有每日一练、组卷、题库、教师资源上传、内容库、充值、管理员和资源审核页面。

### 3.2 生成与数据链路

- Edge `generate` 已区分应用与文档分支；文档分支输出并校验 DocModel，应用分支校验 HTML。
- 生成前后有积分预估、预扣、结算和失败退款设计；积分写操作通过 RPC，不应绕过数据库安全边界。
- 模型适配器支持多 provider，并保留 mock 降级；模型密钥设计为只放 Supabase Secrets。
- 提示词按数据库模板分节、版本化加载；已有教案/课件质量和配图要求相关迁移。
- 教材版本、教材知识、RLS、Tavily 检索适配器和生成阶段 `textbook_search` 已实现；命中知识缓存时复用，未命中时可检索并沉淀为待核对知识。
- 文档沉淀库 `doc_library` 及幂等沉淀函数已存在，生成成功后尝试写入沉淀，失败不阻断主流程。

### 3.3 导出、部署和协作基础

- 浏览器端结构化导出 PPTX/DOCX，复用 DocModel/exportMap，不采用截图导出。
- Three.js 已从 PWA 预缓存中排除并改为运行时缓存，降低首访体积。
- GitHub Pages 地址、仓库、Supabase 项目和 Actions 发布流程记录在现有接手文档中；后续推送通过 GitHub Actions 构建发布。
- `AGENTS.md` 已创建，写明技术边界、角色职责、构建命令、安全红线和 `docs/logs/` 日志规范。

## 四、未完成或不能视为已验收的部分

### P0：内测前必须闭环

1. **教材绑定空状态不可用**：`TextbookCascade` 目前只能筛选已有版本。若 `textbook_versions` 为空，页面只显示“暂无教材版本，可跳过”，没有像互动应用选择那样的新增/上传入口；也没有在该处完成版本元信息、电子教材上传和知识补写闭环。
2. **真实生成链路未被当前环境证明**：Mock 流程可以演示，但真实模式仍依赖 Supabase 迁移完整执行、Edge Functions 部署、模型 Secrets、有效提示词配置、积分配置和 Storage 权限。当前仓库没有本环境真实库联调证据，因此“生成教案显示异常/生成不了”需要按真实环境逐项定位，不能用 Mock 通过替代线上验收。
3. **文档真实版本保存仍有风险**：历史记录指出真实模式 `saveVersion` 曾返回占位的 version/URL；需要在真实 Storage 上验证 `docs/{id}/v{n+1}.json` 写入、版本递增、发布和回读。
4. **线上 SQL/迁移状态需核对**：文档记录的迁移已到 0046，但合并 SQL 文件与单文件清单存在版本差异。必须以目标 Supabase 实际迁移状态和验证 SQL 为准，不可盲目重复执行。

### P1：内测后尽快补齐

- 教材电子版解析、章节切分、知识审核、权限和版本更新体验。
- 文档导出保真度（表格、图片、3D 课件在 PPTX 中的呈现）和真实文件下载回归。
- 分享链接、作者编辑权限、二维码和公开/私有策略的最终确认。
- 真实统计替换首页占位数据背书。
- Skill/知识沉淀的命中率、降本指标、可解释性和删除/撤回机制。
- 内测反馈收集、移动端布局、失败退款、超时、重复提交和跨账号权限测试。

## 五、针对本轮用户反馈的判断

### 5.1 “主页不要在应用广场”

代码路由已经满足：已登录根路径进入生成页，`/square` 独立访问。后续 QA 需验证登录后刷新根路径、未登录首页 CTA、移动端导航和 GitHub Pages 子路径 basename，避免部署环境再次落到 404 或广场。

### 5.2 “绑定教材点开什么都没有”

这是可复现的产品缺口，不是用户操作问题：真实库无版本时，级联选项来自空数组，组件没有创建动作。正确修复方向是新增“新建教材版本/上传电子教材/补写知识”入口，并在创建成功后回填当前选择；校本资源上传页不能直接复用为教材知识入口。

### 5.3 “之前生成的 10 个文档太 low，删掉”

当前仓库和文档没有给出这 10 份文档的确定 ID、账号归属、线上/Mock 来源或是否包含真实用户数据。不能通过清空 `apps`、`doc_library` 或 Storage 桶来代替定向删除。实施前需要用户提供明确清单，或由管理员页面按标题/创建时间/作者筛选后逐条确认；删除动作必须可审计并保留回滚/备份策略。

### 5.4 “上传数据库供网页 AI 学习”

有必要，但应拆成三类数据：校本资源、教材电子版/教材版本、生成后教师核对的知识沉淀。当前已有表和服务雏形，但缺少面向教师的教材上传与知识管理入口，也缺少文件解析、去重、审核、撤回和隐私说明。不能把任意数据库文件直接注入提示词；应走受权限控制的 Storage → 解析/切片 → `textbook_knowledge`/Skill → 检索命中链路。

## 六、潜在问题与风险清单

| 风险 | 影响 | 处理建议 |
|---|---|---|
| Mock 与真实模式差异 | 本地看似可用，线上生成失败 | 先做真实 Supabase 最小闭环，再做发布门禁 |
| Edge TS 不在主 tsc 范围 | 语法错误可能拖到部署才暴露 | 继续运行 `scripts/check-functions.mjs`/esbuild 体检 |
| 迁移文件版本漂移 | 重复执行、枚举和函数报错 | 记录目标库版本，按序执行并跑验证 SQL |
| 教材知识与校本资源混用 | 版权、隐私、检索质量风险 | 分表、分 UI、分 RLS 和数据生命周期 |
| 真实文档 Storage 未验证 | 编辑/版本/分享可能失效 | 用真实账号做写入、回读、发布和撤销测试 |
| 删除演示数据误伤真实数据 | 不可逆数据损失 | 只允许带 ID 的定向删除并先备份 |
| 外部检索内容版权/准确性 | 教案事实错误或侵权 | 生成结果强制“教师核对”，记录来源和待核对状态 |
| 模型、检索和积分配置缺失 | 生成失败或价格不一致 | 发布前检查 Secrets、活动 prompt、cost RPC 和退款 |
| GitHub Pages 子路径/PWA 缓存 | 白屏、404、旧版本表单丢失 | 验证 `BASE_URL`、Actions、PWA 更新策略 |
| 根目录历史临时文件较多 | 维护和发布噪声 | 仅在确认不影响用户后另开清理任务，本轮不删除 |

## 七、当前可执行的验收基线

- 静态检查：`npm run typecheck`、`npm run build`。
- Edge 检查：`node scripts/check-functions.mjs`。
- Mock 冒烟：注册/登录演示、生成应用、生成文档、文档预览、编辑保存、PPTX/DOCX 导出。
- 真实内测门禁：登录、教材创建/选择、教案生成、失败退款、Storage 回读、作者权限、公开分享、移动端和重复提交。

结论：项目不是从零开始，前端与后端骨架、文档生成和教材检索的主要代码已经在盘；但当前最影响内测的两个事实是“教材空状态没有可操作入口”和“真实教案生成链路尚未被线上环境证明”。在确认十份文档的精确删除范围、真实 Supabase 状态和内测验收口径前，不应直接做破坏性数据清理或宣称已可正式推出。
