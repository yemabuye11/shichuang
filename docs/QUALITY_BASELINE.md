# 生成质量摸底报告

> 目的：回答野马最关心的问题——**「我这个平台生成的课件，到底能不能拿去上课、能不能跟别的平台比？」**
> 评估时间：本次摸底
> 评估对象：教案 / PPT 课件 / 3D 课件 / 办公文档 四类产物
> 评估方式：**代码级静态评估 + 成本公式推算**（原因见第一节）

---

## 一句话结论（先看这个）

> **现在还不能打。**
> 办公文档 ✅ 能直接用；教案 ⚠️ 改改能用（要补 20–30 分钟）；
> PPT 课件 ⚠️ 偏 ❌（是个"文字大纲"，没有一张图）；**3D 课件 ❌ 现在是砸招牌状态**——它是最贵的功能（4 积分），但渲染出来的模型跟教学内容基本无关，分享出去的网页甚至打不开。
> **按现在的样子推广，老师用一次就不会来第二次。**

```bash

supabase secrets set SECRET_SALT=随便写一段长随机串

supabase functions deploy generate                   # 部署生成函数
```

**C. 成本**：跑完下面 4 个样本，实际 API 花费约 **0.05 元**（5 分钱）以内。

### 因此本报告的评估方式

**本报告②的质量评分，是基于对提示词模板、渲染代码、导出代码的逐行审查做出的"预判"，不是实测。**
我会明确区分：
- ✅ **确证结论**（读代码能 100% 确定的，比如 3D 渲染逻辑、PPT 导出模板）—— 这些可以直接当事实看；
- 🔶 **预判结论**（内容好不好，取决于模型发挥，只能按提示词设计水平推断）—— 这些配好 Key 后必须真跑一次复核。

## ② 四类产物评估

> 评分说明：5 分 = 下载就能上课；4 分 = 小改即用；3 分 = 要补不少东西；2 分 = 只能当素材；1 分 = 不能用。
> 样本统一用野马最熟悉的课题：**九年级数学 · 二次函数的图像与性质**（办公文档用"九年级家长会通知"）。

### 总览

| 产物 | 内容准确性 | 结构完整度 | 排版精美度 | 直接可用性 | 课堂适用性 | 综合 | 结论 | 老师要改多久 |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|---|
| 办公文档 | 4 | 4 | 3.5 | **4** | 4 | **3.9** | ✅ 能直接用 | 5–10 分钟 |
| 教案 | 3.5 | **4** | 3.5 | 3 | 3 | **3.3** | ⚠️ 改改能用 | 20–30 分钟 |
| PPT 课件 | 3.5 | 3 | **1.5** | **2** | 3 | **2.6** | ⚠️ 偏 ❌ | 40–60 分钟 |
| 3D 课件 | 2 | 3 | **1** | **1** | **1** | **1.6** | ❌ 不能用 | 没法改，得重做 |

### 样本 1：教案（九年级数学 · 二次函数） — ⚠️ 改改能用（3.3 / 5）

**✅ 做得好的地方（提示词设计确实下了功夫）**

- **8 大板块的结构是对的**，而且**每个教学环节都要求写「教师活动 / 学生活动 / 设计意图 / 时间分配」四要素**——这正是教务处检查教案时盯的东西，比很多通用 AI 工具专业。
- 作业要求**分层（基础 / 拓展）**，符合现在"双减"下的作业要求。
- 有 `verifyHints` 机制：AI 没把握的地方会主动列出来让老师核对，**不会不懂装懂**。

**❌ 明确的短板**

1. 🔶 **"骨架完整但血肉不足"（最可能被吐槽的一点）**
   单次输出被硬顶在 **8000 token（约 5000–6000 汉字）**。一份 8 板块、5 个环节的教案，光框架就占掉小一半，剩下写教学过程的空间很紧。
   **预判结果**：环节标题都在，但每个环节只有 2–3 句话，缺少具体的师生对话、追问设计、板演步骤。

2. 🔶 **数学教案最核心的"例题链"没有要求**
   提示词里没有"必须给出 N 道带完整演算过程的例题"。数学教案的命脉就是例题怎么选、怎么递进、怎么变式——**这一条缺了，数学老师拿到会直接觉得"太空"**。

3. 🔶 **时间分配会让 AI 瞎编，且不会自检**
   要求写"时间分配"，但**没有约束"各环节时长之和必须等于课堂总时长（45 分钟）"**。
   **预判结果**：很可能出现 5+10+15+12+10 = 52 分钟这种明显错误，老师一眼看出是 AI 写的。

4. ✅ **确证：提示词里有 3 段在"打架"，会拉高失败率**
   文档生成复用了"生成 HTML 网页应用"的提示词骨架，导致系统提示里同时存在：

   | 段落 | 说的内容 | 对文档生成的影响 |
   |---|---|---|
   | `role` | "把想法实现为**单文件网页应用**" | 任务定位跑偏 |
   | `output_format` | "**只输出一个 HTML 文件**" | **跟"输出 JSON"直接冲突** |
   | `code_quality` | "`use strict`" / `addEventListener` / `innerHTML` | 完全无关，白占约 400 token |

   文档类型模板（`doc_type:*`）虽然追加在后面要求"输出 DocModel JSON"，但**前面那段"只输出 HTML"是个强指令，会显著增加 JSON 格式出错的概率**。
   **后果**：老师点生成 → 等 1–2 分钟 → 弹"这次没生成成功，已退还积分"。**不扣钱，但很劝退。**

**老师拿到手要做什么**：补例题（10 分钟）+ 调时长分配（5 分钟）+ 把环节写具体（10 分钟）≈ **20–30 分钟**。
**值不值**：省掉了查资料和搭框架的时间，但省不了"备课的核心思考"。**对新手老师价值大于老教师。**

### 样本 2：PPT 课件（同课题） — ⚠️ 偏 ❌（2.6 / 5）

**✅ 做得好的地方**

- 页数与逻辑顺序有明确要求（封面 → 目标 → 导入 → 知识页 → 例题 → 小结 → 作业）。
- **`notes`（演讲者备注）是真心不错的亮点**：要求给"怎么讲、开场白、易错提醒、互动提问"。这一条比市面上很多 AI 做 PPT 的工具都细。

**❌ 明确的短板（这是四类里问题第二严重的）**

1. ✅ **确证：一张真图都不会有**
   提示词明确要求"若需要配图，`image.src` 留空，用 caption 注明『建议配图：XX』"。
   **所以导出出来的 PPT，所有图片位置都是一个虚线框写着"建议配图：二次函数图像"的文字。**
   对数学课件来说这是**致命**的——**一节讲函数图像的课，课件里没有函数图像。**

2. ✅ **确证：导出的 PPTX 是"一个模子印出来的"**
   看导出代码，每一页都是同一套：标题 28pt 加粗 + 项目符号 18pt + 白底黑字，**没有第二套版式**。
   - 文档模型里其实有 `layout` 字段（封面/内容/两栏/章节页），**但导出时完全没被读取**，等于白设计。
   - 表格被压成 `a | b | c` 的纯文本行；图片变成 `[图] 说明文字`。
   - 没有配色主题、没有母版、没有校徽位。
   **观感**：像把一份 Word 大纲直接粘进了 PowerPoint。

3. 🔶 **页数下限只有 8 页，对 45 分钟的课偏少**（一般 15–25 页），而且 8000 token 上限会逼着模型把每页压成 3 个要点。

**老师拿到手要做什么**：自己配图（二次函数图像要自己画/截图，20 分钟）+ 重排版式（20 分钟）+ 补内容（10 分钟）≈ **40–60 分钟**。
**分学科的结论不一样**：
- **数学 / 物理 / 化学**（靠图说话）→ 实际是 ❌，**因为没图基本等于重做**；
- **语文 / 历史 / 班会 / 道法**（以文字为主）→ ⚠️，40 分钟能改好，作为内容提纲是有价值的。

### 样本 3：3D 课件 — ❌ 不能用（1.6 / 5）🚨 **最严重的问题**

**这是本次摸底发现的最严重问题，也是最贵的功能（4 积分，是教案的 2 倍）。**

我逐行读了 3D 渲染代码，结论很确定：

**❌ 问题 1：渲染出来的模型跟教学内容基本无关**

| 3D 类型 | 实际渲染出来什么 | 能不能用 |
|---|---|---|
| `function`（函数） | **写死的正弦余弦曲面** `y=sin(x)cos(z)`，**完全不读 AI 给的表达式** | ❌ 讲二次函数，出来的是 sin·cos 曲面 |
| `biology`/`physics`/`circuit`/`custom`（生物/物理/电路/其它） | **同一个通用占位模型：一个蓝方块 + 4 个橙球绕圈** | ❌ 跟具体知识点毫无关系 |
| `globe`（地球） | 一个蓝球 + 4 个金色圆环，没有贴图 | ❌ 很糙 |
| `geometry`（几何） | 正方体/球/圆柱/圆锥/金字塔，基础几何体 | ⚠️ 能用，但很简单 |
| `molecule`（分子） | 球棍模型，化学可用 | ✅ 化学课能用 |

**注意**：野马主推的"3D 课件"如果讲的是**数学函数或物理原理**（最常见的两类需求），落到的恰恰是**写死的 sin·cos 曲面**和**蓝方块+橙球**——**这两个都是跟课无关的通用占位物。**

**❌ 问题 2：分享出去的网页，3D 根本打不开**
发布到 `/d/` 的网页里，3D 部分尝试加载 `/vendor/three.module.js`，**这个路径不存在**。
**实际效果**：一个黑色空框，里面写着"本页未内置 Three.js，请用平台内置「3D 查看器」打开此课件"。
也就是说：**老师在平台内部能看到（虽然内容是假的），但一旦分享给学生/同事，就是个黑框报错。**

**❌ 问题 3：导出 PPT 只剩一页文字**
3D 课件导出 PPTX 时，3D 部分被替换成一页写着"本页为静态预览，建议在网页版交互查看"的纯文字页——**而那个网页版还是打不开的。**

**结论**：3D 课件目前是「**看起来有 3D，实际跟课无关，还分享不出去**」。
**这是唯一一个"老师满怀期待点进去，然后立刻失望"的功能。如果拿它做卖点去推广，是最快砸招牌的方式。**

### 样本 4：办公文档（九年级家长会通知） — ✅ 能直接用（3.9 / 5）

**✅ 为什么这一类反而最好**

1. **AI 最擅长**：通知、方案、发言稿这类文书，事实风险低、格式固定、用语有套路，正好是大模型的强项。
2. ✅ **确证：有一条很专业的设计**——提示词明确要求"缺失的具体信息（学校名、日期、人名）**用占位，不要编造真实机构名**"，并写进待核对清单。
   **这一条非常关键**——AI 最让人不信任的就是瞎编学校和人名，这里直接从提示词层面堵住了。
3. **输出量不撞上限**：一份通知 500–1000 字，8000 token 上限绰绰有余，模型能写得很细致。
4. 结构要求清晰：标题用一级标题、正文分段、要点用列表、排期/分工用表格、落款用段落。

**❌ 短板（都不致命）**

- 没有篇幅引导，可能写得偏短或偏长（可以让"字数"变成老师能填的字段）。
- 没有学校模板库，不同学校的通知抬头格式不一样。

**老师拿到手要做什么**：填学校名、日期、班主任姓名、具体时间点（这些本来就是占位）≈ **5–10 分钟**。
**这是四类里唯一可以放心拿去用的。**

## ③ 野马提的两个产品逻辑问题

### 问题 1：「一次让 AI 生成整学期」会不会白嫖？

**答：钱不会亏，但体验会崩。真正的风险跟你担心的不一样。**

**✅ 成本侧是安全的（这点可以放心）**
单次的产出量被 **8000 token 硬顶**（约 5000–6000 汉字），模型**不可能**真的吐出一学期的量。外面还有三重护栏：
- 日限 30 次/人
- 全局月度阀 `monthlySpendCny = 100` 元
- 单次 120 秒超时

**结论：不会出现"一条请求烧掉几百块"。**

**❌ 但会发生两件伤害体验的事**

| 情况 | 发生时会怎样 | 后果 |
|---|---|---|
| **A. JSON 被截断**（大概率） | 一学期内容写不完 → JSON 残缺 → 校验失败 → 自动重试 1 次 → 仍失败 → **全额退积分 + 提示"生成失败"** | 不亏钱，但老师白等 1–2 分钟，觉得"这玩意不稳定" |
| **B. 模型自作聪明压缩**（更糟） | 把 20 节课压成 20 行提纲塞进 8000 token → **校验通过，正常扣 2 积分** | 老师花了积分、等了 1 分钟，拿到一份**看起来成功了的垃圾**。**这才是最伤的。** |

**按输出量计费现在行不通**（三条理由）：
1. 老师点"生成"之前不知道要花多少积分，违背"零门槛"；
2. 同样一句话两次生成可能差 3 倍，必然引发"凭什么这次扣我 5 分"的投诉；
3. 毛利本来就建立在"平均下来够薄利多销"上，按量计费会算不清账。

**✅ 建议的最小改动（按优先级，都不用改架构）**

| 优先级 | 改法 | 工作量 | 说明 |
|---|---|---|---|
| **1** | **提示词加一句硬约束**（改数据库配置，**不用重新部署**）：<br>"只生成**一节课（1 课时）**的内容。若教师要求整学期/多课时，**只生成第 1 课时**，并在待核对清单里说明『本平台一次生成一课时，请分次生成其余课时』。" | 10 分钟 | 成本最低，直接消灭情况 B |
| **2** | **请求前拦截关键词**：`generate/index.ts` 里对 prompt 检测 `整学期\|全册\|一学期\|所有课时\|全套`，命中直接返回中文提示："一次只能生成一节课哦，请指定具体课时（如『二次函数第 1 课时』），这样质量更高。" **不扣积分** | 5 行代码 | 秒回，不等 1 分钟 |
| **3** | 后置检测：校验时若一级标题超过 3 个，判为超范围 → 失败退款 | 可选 | 兜底 |

### 问题 2：实际 token / 积分消耗，定价合不合理？

> ⚠️ **以下数字是按代码里的成本公式推算的，不是实测。** 配好 Key 跑 4 次就能拿到真实值，届时请回填本表。

**推算基准**（读自配置表）：DeepSeek，输入 1.5 元/百万 token（命中缓存 0.05），输出 4.5 元/百万 token；**高峰时段（北京时间 9–12 点、14–18 点）×2** —— 而这两个时段**恰好就是老师备课的时间**，所以**实际几乎都按高峰价算**。

| 产物 | 预估输入 | 预估输出 | 积分 | 平峰成本 | **高峰成本** | 单次收入* | **毛利率** |
|---|---:|---:|:--:|---:|---:|---:|---:|
| 办公文档 | ~2,100 | ~1,200 | 2 | ¥0.006 | **¥0.013** | ¥0.099 | **87%** |
| 教案 | ~2,100 | ~2,800 | 2 | ¥0.013 | **¥0.026** | ¥0.099 | **74%** |
| PPT 课件 | ~2,100 | ~3,500 | 3 | ¥0.016 | **¥0.032** | ¥0.148 | **78%** |
| 3D 课件 | ~2,300 | ~3,000 | 4 | ¥0.014 | **¥0.028** | ¥0.198 | **86%** |

\* 收入按标准版折算：200 积分 / ¥9.9 = **¥0.0495 / 积分**。（校级版 3000 积分/¥99 = ¥0.033/积分，毛利率约降 10–15 个点，仍为正。）

**结论：**

1. **定价是合理的，而且偏保守——毛利 74%–87%。这是好消息。**
   意味着**我们有充足的余量为了质量多烧 token**。就算把输出上限翻倍（下面第 3 件事会建议这么做），成本涨一倍到 ¥0.05，毛利率仍有 50%–70%，**完全扛得住**。

2. **积分消耗跟真实成本的相关性很弱，但暂时不用改。**
   3D 课件的真实成本只有办公文档的 2.3 倍，却收 2 倍积分（4 vs 2）——看起来"不准"。
   但**定价应该按"老师觉得值多少"，而不是按成本**。3D 收 4 分是因为它 perceived value 高。
   ⚠️ **前提是：3D 得真的值 4 分。按现在"通用占位模型"的现状，4 分是收高了。**

3. 🚨 **真正的成本大头不是生成，是注册赠送 100 积分。**
   新用户白拿 100 积分，若全用完：
   - 全生成教案（2 分/次）= 50 次 → 真实 API 成本 **¥0.65 ~ ¥1.30 / 人**

## ⑤ 最该改的 3 件事（按性价比排序）

### 🥇 第 1 件：把 3D 课件的"假 3D"修掉，或者先下线它
**为什么排第一**：它是**最贵（4 积分）、最主打、现状最差**的功能，是唯一一个"老师满怀期待点进去然后立刻失望"的入口。**这个问题不解决，其他优化全是白做——因为用户第一次用的很可能就是它。**

**两个改法，二选一：**

| 方案 | 做法 | 工作量 | 适用 |
|---|---|---|---|
| **A. 保守止血（推荐先做）** | 生成入口只保留 `geometry`（几何）和 `molecule`（分子）两个真能渲染的类型；`function`/`biology`/`physics`/`circuit`/`custom` 直接提示"该类型 3D 课件暂未支持，请选择几何或分子类型"。 | **1–2 天** | 想立刻止血 |
| **B. 根治** | ① ThreeViewer 的 `function` 分支改成**真正解析 AI 给的表达式**（渲染 y=f(x) 曲线/曲面，或 3D 参数曲面）；<br>② 给 `biology`/`physics`/`circuit` 各做 2–3 个真模型模板（如：细胞结构、凸透镜成像、串并联电路）；<br>③ 修 `renderDoc` 里 `/vendor/three.module.js` 的路径，改成跳平台内 `/3d/` 页面。 | **3–5 天** | 想真做这个卖点 |

**一句话**：**宁可少一个功能，也不能给一个假的。**

---

### 🥈 第 2 件：给 PPT 课件补上"图"和"版式"
**为什么排第二**：PPT 是老师**最高频**的需求，现在的样子（没图、一个模子）会让人直接判定"不如学科网/101 教育PPT"。**这是决定口碑留存的一件事。**

**按性价比排的三步：**

1. **【最高性价比】让 AI 生成真正的图，而不是"建议配图"占位符**
   - 新增一个 `chart` 块类型（折线 / 柱状 / 扇形 / 函数曲线），让 AI 只输出结构化数据（如 `{type:'line', points:[...]}`），前端用**纯 SVG 渲染**。
   - 数学的函数图像、几何图形，让 AI 直接输出 **内联 SVG path**（DeepSeek 能写 SVG）。
   - **这一项就能把数学/物理课件从 ❌ 拉到 ⚠️ 甚至 ✅**，因为"没图"是现在唯一的致命伤。
   - 工作量：**2–3 天**

2. **PPTX 导出支持版式**（读过 `slide.layout` 字段，它现在被白白忽略了）
   - 用 pptxgenjs 的 `defineSlideMaster()` 做 **3–4 套内嵌版式**：封面页 / 要点页 / 两栏页 / 章节页。
   - 加一个配色主题（主色 `#2F6BFF`）+ 校徽位。
   - 工作量：**1–2 天**（能让"观感"提升一个档次，肉眼可见）

3. 页数下限从 8 提到 12–15（在 token 放开之后再做）

---

### 🥉 第 3 件：拆掉打架的提示词 + 放开输出上限
**为什么排第三**：**成本最低（几乎不用写代码），但它同时解决"生成失败率高"和"内容太单薄"两个问题**，是前面两件事的放大器。

**两步，都可以在数据库里改，不用重新部署：**

**第 1 步：给文档类另起一套提示词（改配置表，10 分钟）**
现在文档生成复用了"生成 HTML 网页应用"的提示词，里面 `output_format` 说"只输出 HTML"、`role` 说"单文件网页应用"、`code_quality` 讲 `use strict`——**三段都对文档生成有害**。
→ 在 `prompt_templates` 表新增 `system_section:doc_role` / `system_section:doc_output_format`（明确"只输出 DocModel JSON"），把 `compose.ts` 里 `DOC_SYSTEM_SECTIONS` 的三个 key 换掉。
→ **预期收益**：JSON 格式错误率下降，"生成失败"明显减少；还能省下约 400 token 的无效上下文。

**第 2 步：把输出上限从 8000 提到 16000（改配置，1 分钟）**
- 改 `system_config.limit.maxOutputTokens` 和 `model_profiles.max_output_tokens` 两个值即可。
- **成本影响**：单次成本翻倍（教案 ¥0.026 → 约 ¥0.05），**毛利率从 74% 降到约 50%，仍健康。**
- **预期收益**：教案能写出完整的师生对话和板演步骤，PPT 能写满 12–15 页而不是 8 页。**直接从"骨架"变成"有血有肉"。**

**顺手再补一条（改提示词，5 分钟）**：在 `doc_type:lesson_plan` 里加两条硬约束——
- 「各环节时间分配之和**必须等于课堂总时长**」
- 「必须给出 **3 道以上带完整演算过程的例题**」
→ 直接消灭数学教案最常见的两类硬伤。
