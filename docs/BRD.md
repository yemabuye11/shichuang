## 一、业务背景

### 1.1 业务起源
师创由野马老师（某中学教务/九年级数学教师）发起。在日常教学中，野马老师发现：
- 备课耗时严重，一份完整课件需要 2–3 小时
- 2024 年新教材换版后，旧课件大量作废
- 3D 教学资源稀缺，想讲"圆柱展开"只能找现成视频，无法定制
- 教研组内部资源难共享，重复造轮子

基于以上痛点，野马老师决定打造一款**面向中小学教师的 AI 备课办公台**。

### 1.2 业务愿景
> 让每个中小学教师都能在 5 分钟内拿到一份可编辑、可演示、可分享的备课资料，且永远跟得上教材变化。

### 1.3 业务范围

**P0 包含**：
- 教案生成（Word 文档）
- PPT 课件生成（含 3D 课件）
- 办公文档生成（通知、总结、试卷等）
- 教材版本自动匹配与联网检索
- 教师核对与修正机制
- 积分制与会员体系
- 网页版可演示链接分享

**P0 不包含**（已确认延后）：
- 课堂互动直播
- 学生端 APP/小程序
- 在线作业批改
- 学情分析

## 二、业务目标

### 2.1 北极星指标
**周活跃教师数（WAU）**——每周至少生成 1 个内容的教师数
+ **周生成内容数**（辅助北极星）

### 2.2 阶段性目标

| 阶段 | 时间 | 关键目标 |
|---|---|---|
| **MVP** | 0–3 个月 | 跑通核心闭环（生成→编辑→导出/分享）；演示模式可用；50 个种子用户 |
| **验证** | 3–6 个月 | 100 付费用户；周生成内容 1000+；教师满意度 NPS ≥ 40 |
| **增长** | 6–12 个月 | 500 付费用户；月活跃教师 2000+；月生成内容 10000+ |
| **规模** | 12–24 个月 | 2000 付费用户；校内 SaaS 签约 10 所学校；年营收 60 万 |

### 2.3 业务约束
- **零现金支出起步**：海外免费层 + 客户自购 API Key
- **非程序员运营**：野马本人无技术背景，系统必须稳定可维护
- **教师极简操作**：3 步出结果，不培训
- **数据合规**：AI 生成内容显著标注，教师可改可上传

### 4.3 Skill 沉淀与复用降本机制（🆕 新增核心机制）

> **来源**：野马 2026-09-12 提出——"希望这个版本能有数据存储功能，让更多人来制作，之后生成一个 skill，下次遇到类似情况直接产出，花费的 token 会少一些。"
> **本质**：这是一个**越用越省、越用越快**的飞轮，也是师创长期毛利率的核心护城河。

#### 运作闭环（四步）

1. **生成即沉淀**：每次生成的 `DocModel` 结构化存入内容库，带完整元数据（学科/年级/教材版本/类型/关键词）
2. **授权复用**：教师可选"仅自己可见 / 教研组可见 / 公开到广场"，让**更多人基于已有成果继续制作**
3. **Skill 提炼**：同类内容积累到阈值（建议 ≥100 条）后，自动/半自动提炼出 **Skill**＝结构骨架 + 提示词片段 + 版式模板 + 典型示例
4. **命中复用**：新请求先与已有 Skill 做**语义匹配**；命中则"套骨架 + 局部填空"产出，未命中才走全量 AI 生成

| 步骤 | 技术落点 | 复用程度 |
|---|---|---|
| ① 生成即沉淀 | 复用 T06 的 `DocModel` + Storage；新增 `doc_library` 表 | 高度复用 |
| ② 授权复用 | 复用现有广场 `SquarePage` 与 `category` 筛选 | 完全复用 |
| ③ Skill 提炼 | 新增 `skills` 表 + 提炼任务（先人工审核再上线） | 新增 |
| ④ 命中复用 | `generate` Edge Function 新增 `skill_match` 阶段（在 `textbook_search` 之前） | 新增阶段 |

#### 降本效果（保守估算，按 DeepSeek-V3 输出 ~8 元/百万 token）

| 场景 | 全量 AI 生成 | 命中 Skill 复用 | 节省 |
|---|---|---|---|
| 教案（约 4k 输出 token） | ~0.032 元 | ~0.008 元（仅填空） | **75%** |
| PPT（约 8k 输出 token） | ~0.064 元 | ~0.016 元 | **75%** |
| 3D 课件（约 10k 输出 token） | ~0.080 元 | ~0.020 元 | **75%** |

> 按命中率 40% 保守估算，**整体 token 成本可下降约 30%**；随沉淀库增大，命中率与节省比例还会持续提升——**这正是"涨价保利润"之外的第二条降本路径**。

#### 与现有机制的协同

- 复用 **T06** 的 `DocModel` 结构化源（一份源 → 沉淀/编辑/导出/分享都从它派生）
- 复用 **T07** 的 `textbook_knowledge` 沉淀思路（教材知识 → 内容 Skill，同一套"沉淀-复用"范式）
- 复用 **T04 广场** 的公开/检索/点赞基础设施

#### 实施节奏建议

- **P0（随 T06 一起）**：先做"生成即沉淀"——成本极低，因为 `DocModel` 本来就要存
- **P1（T09）**：做 Skill 提炼 + 命中复用——真正的降本，但需要沉淀量
- **触发阈值**：同类内容 ≥100 条后才自动提炼 Skill，避免过早提炼噪声

## 六、约束与假设

### 6.1 约束
- **技术栈锁定**：Vite 5 + React 18 + MUI 6 + Tailwind 3（不升级）
- **服务依赖**：Supabase 免费层（Auth/Postgres/Storage）+ Cloudflare/Vercel 静态托管
- **成本约束**：零现金支出起步；任何付费项需单独批准
- **运营约束**：野马本人非程序员，系统必须稳定可维护
- **业务约束**：**永远不做在线支付**（兑换码 + 管理员后台是唯一充值通道）

### 6.2 假设
- 客户（教师）愿意接受"邮箱+密码+邀请码"注册方式
- 教师愿意为 AI 备课工具付费（年付 199 元）
- AI 模型 API 价格不会暴涨至无法承受（已通过积分制解耦）
- 海外免费层（Supabase + Cloudflare）在中国大陆可访问（已规划国内迁移）
- 首批种子用户来自野马本人及合作学校（已确认）

### 6.3 依赖
- Supabase 免费层稳定运行（已用 1 年+）
- DeepSeek/qwen 等模型 API 可用（已多适配器适配）
- 教师网络环境可访问境外服务（境内版将用国内云）
